# יחד בסל

רשימת קניות משותפת לכל הבית, עם התראות Push לכל מי שברשימה:

- **הוספת פריטים, בהתראה אחת.** כשמישהו מוסיף כמה פריטים, השאר מקבלים התראה אחת עם כולם ("דנה הוסיפה 4 פריטים: חלב, ביצים…"). ההתראה יוצאת אחרי דקה בלי הוספות, ולכל היותר 5 דקות מהפריט הראשון.
- **"אני בסופר".** כפתור שמודיע לכולם שיצאת לקניות. בזמן הזה כל פריט שמתווסף נשלח מיד, בלי לחכות, ומסומן אצל הקונה בתגית "חדש".
- **זיהוי הגעה לפי מיקום.** שומרים את הסופרים הקבועים בהגדרות הרשימה. כשהאפליקציה פתוחה ואת/ה ליד אחד מהם, היא מציעה להודיע לכולם. המיקום לא נשמר ולא נשלח.
- **סיכום קנייה.** בסוף הקנייה כולם מקבלים מה נקנה, מה נשאר ברשימה, וכמה זמן זה לקח.
- מיון אוטומטי לפי מחלקות בסופר, עבודה במצב לא מקוון, והזמנה לרשימה עם קוד בן 6 תווים.

## איך זה בנוי

| חלק | טכנולוגיה | איפה |
| --- | --- | --- |
| אפליקציה | React + Vite, PWA (אפשר להתקין למסך הבית) | `src/` |
| נתונים והתחברות | Firebase Auth (Google), Firestore | `src/lib/`, `firestore.rules` |
| התראות | Firebase Cloud Messaging, Service Worker | `src/sw.ts`, `src/lib/push.ts` |
| שרת | Cloud Functions: קיבוץ הוספות, שליחת Push, הצטרפות עם קוד | `functions/src/` |

מבנה הנתונים:

- `lists/{listId}`: שם, משתתפים, קוד הזמנה, סופרים שמורים, והקנייה הנוכחית (`trip`).
- `lists/{listId}/items`: הפריטים.
- `lists/{listId}/events`: הוספות מקובצות (נכתבות על ידי השרת), הגעה לסופר וסיכומים. כל אירוע חדש הופך להתראת Push לכל המשתתפים חוץ ממי שיצר אותו.
- `users/{uid}/tokens/{token}`: המכשירים שאישרו התראות.
- `pendingBatches/{listId}__{uid}`: פריטים שממתינים לקיבוץ. רק השרת ניגש אליהם.

## הקמה (פעם אחת)

1. ב-[Firebase console](https://console.firebase.google.com) יוצרים פרויקט, ומעבירים אותו לתוכנית **Blaze** (נדרשת ל-Cloud Functions. בשימוש של משפחה זה נשאר בתוך המכסה החינמית).
2. **Authentication**: מפעילים את Google כספק התחברות.
3. **Firestore**: יוצרים מסד נתונים באזור `europe-west1`. אם בוחרים אזור אחר, צריך לעדכן את `region` ב-`functions/src/index.ts` וב-`src/lib/firebase.ts`.
4. **Project settings > Your apps**: מוסיפים Web app, ומעתיקים את הערכים ל-`.env.local` לפי `.env.example`.
5. **Project settings > Cloud Messaging > Web Push certificates**: יוצרים מפתח, ושמים אותו ב-`VITE_FIREBASE_VAPID_KEY`.
6. מעדכנים את מזהה הפרויקט: `npx firebase-tools use --add`.
7. פריסה:
   ```bash
   npm install && npm --prefix functions install
   npm run deploy
   ```
   האפליקציה תעלה לכתובת `https://<project-id>.web.app`. אם משתמשים בדומיין אחר, מגדירים אותו ב-`APP_URL` של הפונקציות כדי שלחיצה על התראה תפתח את הכתובת הנכונה.

## פיתוח מקומי

```bash
npm install && npm --prefix functions install
npm run emulators        # Auth, Firestore ו-Functions מקומיים (דורש Java)
# בחלון נוסף, עם VITE_USE_EMULATORS=true ב-.env.local:
npm run dev
```

במצב אמולטור מופיעים במסך הכניסה שני כפתורי "כניסת בדיקה", כדי לנסות את הרשימה עם שני משתמשים בשני חלונות. הפונקציה המתוזמנת שמשחררת את הקיבוצים לא רצה באמולטור, אבל אפשר לראות את `pendingBatches` מתמלא, ואת השחרור המיידי כשמישהו בסופר.

בדיקות: `npm test` (מיון למחלקות, חישוב מרחק) ו-`npm --prefix functions test` (קיבוץ ונוסחי ההתראות).

## מגבלות ידועות

- **אייפון:** התראות Push באתר עובדות רק מ-iOS 16.4 ואילך, ורק אחרי "הוספה למסך הבית". האפליקציה מציגה הסבר כשצריך.
- **זיהוי הגעה ברקע** (כשהאפליקציה סגורה) לא אפשרי באפליקציית ווב. אם נרצה אותו, השלב הבא הוא לעטוף את האפליקציה ב-Capacitor ולהשתמש ב-geofencing של המערכת.
- מי שפתח את הרשימה נשאר הבעלים שלה גם אם עזב אותה.
